# FireSim Docs

The RST files remain the source of truth. This project follows
[Chipyard's Starlight docs setup](https://github.com/ucb-bar/chipyard/tree/e602d917dcc495c58cabe906535e411707096c9c/docs):
`scripts/sphinx_to_starlight.py` renders them with Sphinx and converts the article
HTML into Markdown under `src/content/docs` before Astro starts or builds.
The bridge, watcher, sidebar components, styles, and Read the Docs version
selector are adapted from Chipyard.

## Local development

Use Python 3.12 (either the FireSim documentation conda environment or a virtual
environment) and Node.js 22, as selected by `.nvmrc`. For example, from the repo root:

```sh
python3.12 -m venv /tmp/firesim-docs-venv
source /tmp/firesim-docs-venv/bin/activate
python -m pip install -r docs/requirements.txt
cd docs
eval "$(fnm env --shell bash)"
fnm install --use
npm ci
npm run dev
```

The Node commands assume `fnm` is installed; an existing Node.js 22 installation
or another version manager works too. The existing `conda-reqs/docs.yaml`
environment supplies the Python dependencies without changing FireSim's toolchain
lockfile. Install Node separately, as Chipyard does, to avoid conda ICU conflicts.

`npm run dev` watches the RST sources, images, Sphinx configuration, and included
files (including YAML and Scala/C++ examples outside `docs`). It regenerates the
Markdown and restarts Astro automatically after edits, additions, and deletions.
Astro handles edits to the Starlight components and styles. The bridge defaults
to `SKIP_URL_CHECK=1` so unpushed branches and offline previews work; set
`SKIP_URL_CHECK=0` to enable FireSim's GitHub URL validation.

## Build and preview

```sh
cd docs
npm run build
npm run preview
```

The static site is written to `dist`. Starlight's built-in Pagefind search index
is generated during the production build; use `npm run preview` to test search.
`npm run sync` runs only the RST conversion, and `npm run build:astro` builds
already converted content. Generated Markdown, copied Sphinx assets, and legacy
redirects are ignored by Git. Do not edit them directly.

The original Sphinx commands remain available for RST debugging and downloads:

```sh
SKIP_URL_CHECK=1 sphinx-autobuild . _build/sphinx-autobuild --host 127.0.0.1 --port 8000
make html
make latexpdf
make epub
make formatcheck
```

The PDF build requires a local LaTeX installation. `make html` produces the
Sphinx preview in `_build/html`; `npm run build` produces the published Starlight
site. `make clean` removes generated output for both.

## Navigation and RST features

Keep pages in their existing RST directories and add them to the appropriate
`index.rst` toctree. `src/sidebar.mjs` mirrors FireSim's top-level toctree groups.
Groups with directory indexes use Chipyard's autogenerated dropdowns; their
landing pages become clickable group labels, and children follow toctree order.
Groups without an index list their pages explicitly in `src/sidebar.mjs`; update
that list when adding a page to one of those groups.

Sphinx continues to resolve substitutions, custom GitHub roles, references,
includes, and tabs. Starlight provides the page outline, syntax highlighting,
and code copy buttons. The original Sphinx tabs script and stylesheet provide
tab interaction. Legacy case-sensitive `.html` links redirect to the new routes
and preserve section anchors.

## Versioned docs and Read the Docs

`.readthedocs.yml` uses the same custom HTML build as Chipyard: install Node
packages, run the bridge, build Astro, and copy `dist` into RTD's HTML output.
RTD continues to build PDF and EPUB downloads with Sphinx, and offers HTML ZIP
downloads. CI checks both the original Sphinx output and the Starlight build.

Read the Docs owns production versions. Each active branch or tag builds from
its own checkout and is served at `/en/<version>/`. The version selector uses RTD
Addons metadata, including Chipyard's fallback for older version lists, and is
hidden in local previews. Switching versions preserves the original Sphinx page
path, query, and anchor so existing releases built with Sphinx remain reachable.
A page must exist in the selected release for its link to resolve. Existing
release tags keep their original build configuration and theme.

Astro derives its base path from `READTHEDOCS_LANGUAGE` and
`READTHEDOCS_VERSION`. To test a production-shaped URL locally:

```sh
DOCS_BASE=/en/latest npm run build
DOCS_BASE=/en/latest npm run preview
```

The default site URL is `https://docs.fires.im`; `DOCS_SITE_URL` overrides it.
Active versions and the default version remain configured in the RTD project.
